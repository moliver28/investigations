# Power Network UI v3 — Entity-First Rebuild Implementation Plan

> **For Hermes:** Execute task-by-task. Each task has a deterministic gate. Verify before advancing.

**Goal:** Replace the single-canvas SVG power map (`evidence/11-power-network.html`, 2.4MB, drawer-opens-below-fold, 12–16px click targets) with an entity-first interface: a split-view shell (map + sortable entity directory), full entity pages with ego-networks, canonical relationship classes, and tier-band power presentation — shipped as a folder bundle.

**Architecture:** Python build pipeline emits a **folder bundle** (`evidence/network/{index.html, app.css, app.js, data.js}`) from the canonical graph (`evidence/29-power-graph-v2.json`) plus the 163 researched profiles (`profiles/*.md`). A new **normalize** stage maps 109 verbatim relationship types → 8 canonical classes, written back into the graph data (with verbatim `relationship` preserved alongside a new `rel_class` field). Entity pages render on demand from an in-memory `NODE_DATA`; the ego-network is computed client-side from the same edge list. No framework, no CDN — vanilla JS + inline SVG, same as today, so the bundle opens by double-click offline.

**Tech Stack:** Python 3 (existing venv: `networkx`, `numpy`, `markdown`), vanilla JS, inline SVG, CSS custom properties. Reuses `scripts/compute_power.py` unchanged as the single source of truth for scoring.

## Priority Order (governing constraint — resolve every trade-off against this)

1. **Simple navigation and architecture + a clean, easy-to-read UI. This outranks everything else.** Prefer fewer surfaces, fewer controls, fewer states. Any feature that would add a surface, a mode, or a competing control gets cut or folded into an existing one.
2. **Entity-first content that reads cleanly** — directory, entity page, ego-network, profile.
3. **Missions** — lowest priority; only as a quiet integrated layer that adds no new surface.

**Nav budget (enforced by gate 13):** exactly three primary states (split view → entity page → back), one modal (Method & Sources), zero tabs, zero nested menus, zero onboarding overlays. Any entity reachable in ≤2 actions; any top-level function in ≤1.

## Content–Mission Alignment (content order = mission arc)

The missions teach a five-step arc about how power works. The site's content architecture follows the **same arc**, so the missions are native to the content rather than bolted on:

| Mission (in content order) | What the content already shows | Where it lives |
|---|---|---|
| 1. Who is most powerful? | Directory sorted by rank by default; tier band on every row and in the entity header | directory default sort · entity header |
| 2. Where does their power come from? | "Where power comes from" leads the entity narrative; gold money-source callout | entity page |
| 3. Follow the money | Money toggle on the map + money-class chips in connections | map toolbar · entity connections |
| 4. Who are they connected to? | Connections grouped by the 8 canonical classes with verbatim labels; ego-network | entity connections + ego-network |
| 5. What does it all mean? | Method & Sources modal: tier bands, the composite formula, veto bonus, hub caps | header → modal |

**Mission implementation rules (lowest priority, no new surface):**
- One quiet guide strip integrated into the directory header — mission number, one-line prompt, a "Dismiss" action (aria-label "Dismiss missions") deliberately NOT named "skip", to avoid collision with the accessibility skip link. No overlay, no coach marks, no progress dots competing with content.
- Real completion detection retained (the proven v2 pattern): a mission advances only when the user actually performs the action — open an entity, toggle money, follow a connection, open the method modal.
- **Mission 1 must NOT auto-complete on load:** the directory's default sort IS by rank, so a naive 'sort by rank' trigger fires immediately on open. Define completion as opening the top-ranked entity (or explicitly clicking the rank column header).
- `localStorage` first-run state; after completion or skip the strip collapses to a one-line "Replay" link. A user who never engages sees zero added UI.
- **Alignment is a build-time invariant:** `app.js` carries a `MISSION_CONTENT_MAP` constant naming the exact selectors/sections each mission teaches; gate 14 fails the build if any referenced selector is missing. If the entity narrative order or the directory default sort changes, the mission text updates in the same commit.
